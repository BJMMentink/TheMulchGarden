# God’s Eye View integration

## Current stage

The `World` carousel page embeds the genuine upstream God’s Eye View app, vendored under `vendor/gods-eye-view` from [bilawalsidhu/gods-eye-view](https://github.com/bilawalsidhu/gods-eye-view) (MIT license). It is not a visual re-creation. The page and its key-management API are restricted to signed-in `user` and `admin` accounts. The companion app independently checks the same HttpOnly Mulch Garden session before returning its document or serving its API routes, so hiding the navigation item is not the security boundary. Guests cannot open the app or query its runtime configuration.

For local development, `node server.js` starts Mulch Garden on its configured port (4173 by default) and the Vite companion on loopback port 4175. The embedded app uses the same hostname with a different port, so the host-scoped session cookie accompanies its member checks. The embed preserves God’s Eye's native side panels, layer filters, and POWER UP control. Three independent guides—“Keys,” “How it works,” and “Free vs. keyed data”—sit below the app; the page height grows as they open.

Cloudflare Pages serves the built static app from `/godseye/` on the same site origin. Its Pages Function checks the Mulch Garden session before returning app assets; the Worker provides the app URL, encrypted per-account key routes, and a limited set of authenticated keyless feeds. The Pages project needs the God’s Eye build command and `_site` output described in `cloudflare/README.md`; verify those settings and both production deployments before claiming a local change is live. Cloudflare is still not full upstream feature parity. Never expose the local Vite companion directly to the public internet.

The upstream package requires Node `>=24.14 <25` or `>=26 <27`. If its ignored `node_modules` folder is absent, install the vendored app's dependencies from `vendor/gods-eye-view` (for example, `npm ci` using the upstream lockfile), then start Mulch Garden from the repository root. No visitor downloads are required: the integrated application is delivered in the website iframe. Internet access is still needed for the app's remote assets and public-data sources.

## Provider-key behavior

The native `POWER UP` area saves Google Maps, OpenAI voice, AISStream, NASA FIRMS, TomTom, Cesium ion, OpenSky, and Launch Library keys separately on each account. The local companion reads only the signed-in member's key for supported provider routes. The hosted Worker stores keys and returns browser-provider keys only to their owner, but its new public CelesTrak, ADSB.lol, Launch Library, and NOAA routes deliberately need no personal key. It does not yet use saved TomTom, FIRMS, AISStream, OpenSky, or OpenAI keys for their hosted data/voice routes. A saved key alone does not activate those features. The strict-$0 baseline enters no keys. Optional provider keys can expose their owner to provider charges; Cloudflare does not pay those charges.

Both the local Node API and Cloudflare Worker enforce authentication and scope each record to the session's user ID. The stored envelope uses AES-256-GCM with a fresh 96-bit IV for each save and authenticated additional data bound to the app, envelope version, user ID, and provider. The normal status API returns labels and configured/enabled flags only; the authenticated runtime API intentionally reveals enabled browser-provider keys only to their owning user's browser, where Cesium/Google need them. Browser-side map keys are visible to that user's browser and the provider; users should restrict keys by allowed website/API and quotas. The OpenAI key stays server-side.

Local development automatically creates `data/godside-key-encryption.secret`; `data/` is ignored by Git. This is a local-development convenience, not strong protection against full-device compromise because the local key and ciphertext live on the same computer. The Node preview stores users and app data in local JSON files, not Cloudflare D1. A first local admin can be created only from a loopback connection while that store is empty; its password is hashed and setup closes once an account exists. Production requires a separate Worker secret named `GODSIDE_KEY_ENCRYPTION_SECRET`, encoded as base64url from 32 random bytes. Never put it in source, D1, browser runtime config, logs, or chat. Back it up securely: losing or rotating the secret without re-encrypting existing records makes them undecryptable.

The Cloudflare integration source includes the Pages asset gate, same-origin app route, and D1-backed encrypted native-key endpoints. Apply `cloudflare/migrations/0005_add_godside_provider_keys.sql` to an existing D1 database (fresh installs use `cloudflare/schema.sql`) and set the Worker secret through Cloudflare's secret manager when preparing a deployment. The Worker does not run the local Vite companion or OpenAI resolver. The hosted version still has no camera catalog/frame/HLS proxy route; do not count on Cloudflare CCTV functionality yet.

## Keyless hosted-feed coverage in this checkout

- Esri/OpenStreetMap/OpenFreeMap imagery and simulated road traffic need no provider key. USGS earthquakes, NASA GIBS recent imagery, and mapped ALPR-camera tiles use browser-side public sources. The bundled data-center, submarine-cable, and dam overlays are static app assets; opening a large overlay downloads an asset through the protected Pages gate, not a continuous feed.
- CelesTrak TLE groups (`stations`, `visual`, GNSS, GEO, optional Starlink and active) are on fixed allowlisted URLs. The Worker caches upstream responses for six hours; the browser only requests the groups the selected layer needs.
- Civil aircraft use the public ADSB.lol feed within 250 nautical miles of a validated map center, rounded to a quarter degree for a shared 30-second edge cache. Military aircraft use its public `/v2/mil` feed with a 30-second edge cache. These public feeds can still throttle or disappear; no OpenSky credential is required for this hosted baseline. Track history and aircraft enrichment are not yet hosted.
- Launch Library's unauthenticated recent-launch feed is shared in stable 15-minute cache windows; a stored optional Launch Library token is not sent to that hosted feed.
- NOAA/NHC active-storm positions/advisories use a fixed public endpoint with a five-minute edge cache. The lightweight hosted route does not fetch forecast-cone/track GIS geometry.
- The no-key TomTom status reports that the hosted app should use its OpenStreetMap/simulated traffic fallback; a saved TomTom key does not turn on an unimplemented live tile route.
- The mapped-installations route signals that Overpass is not configured, which makes the upstream layer fall back to its browser-side OpenStreetMap vector tiles and bundled names. Exact Overpass and Google Places search remain unavailable hosted.

All of these feed routes run after the Worker session check, so guests cannot query them through the site. They are available when the app requests them; this change does not force every data layer on at initial page load. These route changes must be deployed and tested on Cloudflare before they appear in production. Public/no-key weather radar, wind grids, transit, bikeshare, fire perimeters, directions, radio, CCTV, and other upstream routes are not all available there yet. Those need separate safe bounds, provider-term review, and cost controls; they should not be represented as working hosted layers. Local ADS-B also requires a visitor's own receiver hardware and browser device access, unlike the public Live Flights feed.

## Free-tier and provider boundaries

As checked on 2026-10-05, Cloudflare Workers Free includes 100,000 combined Workers/Pages Function requests per day, resetting at midnight UTC, and 10 ms CPU per invocation. The member gate in `functions/godseye/_middleware.js` runs for each request under `/godseye/`, including app assets, so those protected asset requests invoke a Pages Function; a static request is free/unlimited only when it does not invoke a Function. The member gate also fetches the API Worker to check the session. Each `/api/*` browser request passes through `functions/api/[[path]].js` and then the API Worker; budget conservatively for both invocations and verify the actual counters in Cloudflare. Edge caching reduces *third-party* fetches, not these incoming member requests. D1 Free includes 5 million rows read/day, 100,000 rows written/day, and 5 GB total storage. Free limits stop/reject excess work; they do not automatically move the account to a paid plan. The Cloudflare app allows one owner/admin plus up to three members. Check Cloudflare's usage dashboard rather than treating this as a guarantee.

The aircraft layer polls about once every 30 seconds while active: roughly 120 browser feed calls per hour per viewer. Four viewers using it for one hour each would create about 480 browser feed calls that day; conservatively budget up to roughly twice that for the Pages-Function-to-Worker path, plus protected assets, session checks, and any other layers. Satellite groups and launch/cyclone feeds have slower refresh cadences, but each member request still consumes route capacity even when an upstream edge cache hits. Keep unused layers off; do not enable automatic camera fetching to make a demo appear populated.

Those hosting limits do not make external APIs free. The bundled God’s Eye docs currently identify: NASA FIRMS free map keys with a 5,000 transaction/10-minute limit; TomTom's current no-card free plan with 200,000 Flow/Incidents vector-tile requests/month (over-limit requests return 429); Launch Library 2 with 15 free unauthenticated requests/hour; Cesium ion Community as $0 only for eligible individual personal/non-commercial use and finite quotas (currently 1,000 Google Photorealistic root tiles/month and 15 GB streaming/month); AISStream as advertised free but without formal terms documented; and OpenSky as restricted to research/non-commercial purposes. Google Map Tiles requires billing: its Photorealistic 3D SKU currently has 1,000 no-cost billable tile events/month, with additional returned tiles billed by use. The renderer may request many tiles; Google's published daily root-tile quota is not a monthly spend cap. For a guaranteed $0 baseline, keep this key empty. OpenAI voice/summaries are usage-billed. Treat provider limits and prices as changeable. Never enable provider billing on behalf of a user.

Other upstream/local sources use public/open or community data such as NOAA weather, public transport, and camera catalogs, but “no key” does not mean unlimited or unconditional: services can require attribution, limit interactive use, restrict commercial use, change access, or go offline. Open-Meteo is used for some cockpit weather; its no-key free API is limited to non-commercial use, currently 10,000 calls/day, with no uptime guarantee. The current hosted Cloudflare source does not proxy every upstream feed; unavailable features should not be mistaken for extra provider usage or a reason to buy a key.

## Camera loading and request budget

The bundled CCTV panel and data layer start off. Opening the page does not fetch a camera catalog or camera frame unless a shared scene explicitly turns the layer on. When the member turns it on, the local companion fetches camera metadata/catalogs, but does not download a still for every listed camera. The ambient layer caps visible camera cards at 20–40 based on zoom, caps the cold-start burst at four in-flight frame requests spaced 250 ms apart, then permits at most one ambient-card fetch per second. Ambient stills refresh on conservative source-aware intervals (typically 3–5 minutes; Fintraffic uses 10 minutes). The selected camera preview can refresh every 10 seconds while active; idle cameras use a 60-second cadence. Auto-hop starts off. The live-video implementation caps two simultaneous sessions and is lazy, but this implementation lives in the local Node companion—not the current Cloudflare Worker.

Accordingly, a first visit to the Cloudflare God’s Eye route does not start CCTV work. CCTV still/video feeds are not yet supported by the hosted Worker. When/if those endpoints are added, they should preserve the upstream client pacing and add per-account daily request/byte caps and an admin kill switch before being exposed. Public camera feeds are third-party sources: local use may consume their bandwidth and is subject to each source's terms, but frame traffic is not presently served by Cloudflare in this integration.

The strict-$0 Cloudflare baseline therefore means: keep optional provider keys absent unless a member deliberately supplies one, leave Google/OpenAI off unless the member has independently set provider quotas and accepts possible charges, and keep any future Cloudflare camera proxy behind bounded, user-triggered requests. It cannot guarantee third-party services will remain free.

## Relevant files

- `src/app.js`: carousel, member navigation, and guest/member/admin access boundary.
- `src/godside.js`: panel markup and three help accordions.
- `src/godside-crypto.js`: shared provider allowlist and authenticated encryption.
- `vendor/gods-eye-view`: actual upstream app and its package manifest/lockfile.
- `server/godside-view-server.js`: starts the loopback-only Vite companion and strips global provider keys.
- `vendor/gods-eye-view/server/standalone/mulch-garden-integration.js`: per-request session gate and user-scoped provider-key context.
- `server/controllers/godside-keys-controller.js`, `server/lib/local-encryption-secret.js`: local API and dev key lifecycle.
- `cloudflare/src/index.js`, `cloudflare/src/godside-public-feeds.js`, `functions/godseye/`, `cloudflare/migrations/0005_add_godside_provider_keys.sql`: Cloudflare app/key routes, authenticated public feeds, member-only static-asset gate, and D1 storage.
- `public/_headers`: site-wide CSP and microphone policy; the Cloudflare app route adds its same-origin frame policy.

## Provider integration checklist

Before activating a provider, separately review current terms, pricing, quotas, required attribution, referrer restrictions, and whether the user's requested free-only boundary can be enforced. Keep keys per-user. Never send OpenAI keys to a browser. Prefer a server-side proxy for secrets; if a provider requires a browser key, explain that it is visible to that user's browser and require provider-side restrictions. Add a hard quota/cost-control path where the provider supports it, test both local and Cloudflare backends, and update this document. Any upstream route not listed in the keyless hosted-feed section still needs an authenticated Cloudflare implementation before that feature is represented as operational there.
